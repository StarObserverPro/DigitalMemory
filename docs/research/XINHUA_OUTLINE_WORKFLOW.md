# 新华街路口：可复用的近景轮廓制作流程

2026-10-27 收录。用户认可路口当前空间与视觉表现可先入库，并要求移除电线、保留简化路灯。[选定场景](../../scenes/xinhua-junction-outline/README.md)是可独立启动的近景样本：接受基础为 `outline-motion-r4-04`，删线后的收录版为 `outline-motion-r4-05`；空间数据仍为 `outline-street-r4-02`。

这份说明记录能重用的方法和约束，具体代码与文件校验值由场景目录、manifest 和验证记录承载。它适用于一个有真实位置依据、可连续走动的小街区近景，不把整张城区总览改成此种渲染。总览的手绘栅格规则继续由 [HANDPAINTED_MAP_ART](../HANDPAINTED_MAP_ART.md) 管理；位置、时间、session 和正式入口继续归 [ARCHITECTURE](../ARCHITECTURE.md) 的既有所有者。

## 先确定要保留什么

这块场景的辨识度来自街道朝向、两侧建筑的高度关系、建筑退界形成的开敞前场、大小不齐的底商和后方塔楼。绘制首先保留这些关系，才轮到人物、车、树和动态线。不能用统一窄人行道、整齐店面阵列、几层楼图标替代已经核对的关系。

输入分为三类，不能相互冒充：

| 输入 | 用途 | 约束 |
| --- | --- | --- |
| 带坐标的道路、建筑轮廓和来源记录 | 建立方向、位置、尺度与稳定 ID | 原轮廓留存；展示简化另存；高度单列证据 |
| 多点街景与卫星/俯视参考 | 核对地面退界、街侧、层数类别、遮挡与前后关系 | 保留拍摄日期及视向；现代图像不自动代表回忆年代 |
| 用户纠正与视觉选择 | 修正地点身份、取舍与表现方式 | 当前明确纠正优先；视觉认可不转化为历史认证 |

三里8号楼是餐厅东北侧后方、三栋高塔中最西侧的一栋，层数按用户明确纠正为24层；71.1米只是既有绘制规则的换算值。其他楼高仍有估计性质。两个入口的位置各保留约15米的不确定性；西侧30米是沿道路中心线的计算范围。这些是本样本数据，不应复制到新街区。私人居住信息不进入场景、文档或公开记录。

## 从证据到可行走场景

1. **划定最小范围与观察方向。** 写清路口、街侧、四至、关键建筑和真实 consumer 相机。先对齐哪个方向是北、哪侧在前，避免拿一个斜向全景画面直接搭左右对称的街谷。
2. **交叉检查多点位。** 同一建筑至少从不同路段核对可见面与前后层次，结合俯视图检查屋顶/地面边界。全景拼接与广角会拉伸边缘，近大远小也会夸大楼高；不能直接拿画面宽高比作为米制尺寸。地图视口中心不是入口坐标，地图坐标系也不能直接当 WGS84 使用。
3. **冻结空间底稿。** 统一局部米制坐标、朝向和源 ID，保留源轮廓与简化展示轮廓。道路、导航和碰撞使用同一坐标框架。退界、独立底商、开敞前场与后排高楼分别可改；外观简化不能挪动地点或凭空开门。
4. **先看素模与路线。** 连续走到范围端点，转向看楼高、间距和遮挡。空间未对齐时不靠线条或配色修饰。只构造有意义的局部，不为一个入口补完整小区内部。
5. **建立轮廓语法。** 用下面的连接和遮挡规则画主线，再验证实际显示大小。人物、车辆、树分别遵守有限笔数；动态短线最后添加，不能补救建筑主轮廓本身不准。
6. **局部修改、固定视图复查。** 同位置、视向、缩放检查前后变化，同时转到正面、侧面、斜向与近裁剪处检查。只修改受影响的对象/画法，不重新生成所有已认可空间。
7. **按修订入库。** 选择唯一可启动版本，保留必要代码、数据、依赖许可、校验值、流程和简洁验证结果。试画、截图流水账、原始照片与私人素材继续留在库外。

Marble 2 重建可帮助检查空间，但生成结果本身不是地理或历史证据。本样本运行时使用实时几何和轮廓，没有依赖生成图片、街景纹理或远端模型。以后选择工具时以是否改善上述空间判断为准，不把模型名称当作交付要求。

## 轮廓要靠结构成立

主线保持平直、流畅、连续；次级线只在少量边角表示运动或声音。配色次于线条组织。不要用随机抖动、密集窗格、排线、噪声、重复描边或表面涂鸦制造所谓手绘感。

| 对象关系 | 绘制规则 | 检查重点 |
| --- | --- | --- |
| 门框—建筑 | 门的倒 U 形与楼底相接，删去开口对应底线 | 一个连续开口；避免闭合矩形压在楼底线上 |
| 窗框—建筑 | 窗框与边角、楼底及相邻窗之间留清楚间距 | 真实外法线与面方向一致；不因相机角度合成黑团 |
| 轮圈—车体 | 前方轮圈使后方车体线局部让开；挡风线留边距 | 侧向与斜向保持明确分工；端视过窄轮圈可省略 |
| 树—路沿、细物体之间 | 按前后深度，保留前景线、裁掉后方线的一小段 | 空隙随视角更新；不在灰色路面刷白色光晕 |
| 建筑大体量—其他物体 | 使用正常填充与深度遮挡 | 不把小物体的留缝规则扩大成整栋建筑的装饰白边 |
| 人物头—躯干 | 头、颈、躯干、四肢构成一条闭合周界 | 不是球形头顶在身体上；步态中不自交、不翻面 |

原型使用屏幕像素笔宽，避免近远变化时轮廓忽粗忽细。粗线跨越实体边界，可能被自己的填充切薄；当前代码采用与像素笔宽相关、受上限约束的微量深度偏移，仍保留前方物体的遮挡。不能用整体关闭 depth test 修复。

小物体遮挡用投影椭圆/线段遮罩裁切黑线片元，并跳过物体自己的笔画。遮罩只在正深度有效；跨过视点平面的椭圆必须跳过，避免异常投影误删半屏线条。线段深度用透视对应的倒数插值。近乎端视的轮圈用不同显隐阈值避免抖动。这些是当前 Three.js 实现策略；其他渲染器可以替换实现，但要保留同样的视觉结果。

## 动态是少量标点

建筑短线随行走触发，顺势弧与放射弧交替；同一时刻只强调一处建筑。停止后收完即停，单纯转相机不触发新的建筑提示。附近短线略长，稍远可见树木也可轮流获得提示。商店门窗偶尔给两根声音弧线，与汽车引擎提示共用名额，不能叠成新的密集层。声音线是表现符号，不是历史声源或音频记录。

**始终保持实黑与固定粗细，通过伸出、缩短、收起出现或消失，不使用淡出。** 树木微摆与人物腿部运动都应轻量；人物步态按实际移动距离驱动，停止回到站姿。菜单/隐藏页面暂停动态，减少动态偏好关闭环境短线和树摆动。

以下是本版调参起点，复用时需在新画面中重新验收，不能当作通用物理常数：

| 参数 | 当前值/预算 |
| --- | --- |
| 主线 / 细节线 / 地面线 | 3.5 / 2.9 / 2.2 CSS px |
| 小物体前景线外的留缝目标 | 约2.5 CSS px，受透视和抗锯齿影响 |
| 建筑短线 | 一组两根；近处长度倍率1.1—1.65；一轮5.8秒，伸出1.15秒、收起1.5秒 |
| 树木提示 | 一组两根；选择约58米内可见且投影足够大的树，约60米范围内绘制 |
| 声音提示 | 商店约18米内；一组两根，与汽车轮流；商店事件间隔约12.8秒 |
| 同时出现的环境短线 | 最多六根，属于上限而非必须填满的配额 |
| 车辆 / 树 / 建筑细节 | 每车最多四笔；树冠加树干两笔；每楼只选一个面，最多四个必要框 |

## 电线省略，路灯简化

用户明确选择不画电线：跨时期变化大，额外查证难以改善这段记忆表达，而且绘制与遮挡成本高。默认不研究、不生成、不保存电线布局，也不为了填空再加装饰线。路灯保留稀疏的简化轮廓，用于街道尺度感，不声称精确型号、位置和年代。

这项取舍可用于后续同类近景。只有某根电线/电杆本身承担明确记忆或事件意义、并被新的用户要求选中时，才作为单独局部对象重新处理；可见现代设施不自动成为历史场景的必画项。

## 验收、复用和正式接入

| 维度 | 必须取得的证据 | 不足时如何处理 |
| --- | --- | --- |
| 空间 | 多点位/俯视关系、源 ID、四至与高度类别；实际路径检查 | 标记未知/近似，不补造年代或精确路线 |
| 轮廓 | 正、侧、斜视与近裁剪下检查接缝、粗细、让线和填色 | 修复局部轮廓或遮罩，不移动真实建筑来迁就画面 |
| 动态 | 行走触发、停止收起、相机旋转、远树、店/车交替与数量上限 | 先减数量，保留主轮廓与注意力层级 |
| 可用性 | 独立启动、实际键盘/点击行走、转向、菜单与缩放 | 测试通过和实际浏览器通过分开记录 |
| 收录 | revision、文件哈希、依赖许可、文档链接、用户认可范围 | 未测项保持未测，不把旧版本证据标成当前通过 |

新场景优先重用连接规则、动画预算、验证方法与模块职责，替换地点数据和场景参数。`drawing.mjs` 负责展示，`ink-occlusion.mjs` 负责细物体让线，`motion.mjs` 负责动态短线，`avatar.mjs` 负责连续人物周界，`navigation.mjs` 负责局部行走；这些文件是本样本实现，不是另建一套项目所有权。

正式接入主应用时，必须另行把样本行走状态接入现有 session、位置接入 spatial registry、年代交给 time resolver，并验证进入/退出恢复与加载失败。样本自己的相机、localStorage 和 RAF 不能与主应用同时争夺输入或状态。此次只收录选定近景及方法，不替换入口，不激活后续接入工作。

收录状态与本次实际验证见 [任务记录](../attention/tasks/DM-STREET-20261027.md)及[场景验证记录](../../scenes/xinhua-junction-outline/evidence/README.md)。旧版几何/动画证据保留其原 revision；用户的路口认可不表示所有端点、所有年代或其他街区已获得美术和史实认可。
