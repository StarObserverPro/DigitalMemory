# 新华街路口：可复用的近景轮廓制作流程

2026-10-27 收录。用户认可路口当前空间与视觉表现可先入库，并要求移除电线、保留简化路灯。[选定场景](../../scenes/xinhua-junction-outline/README.md)是可独立启动的近景样本：接受基础为 `outline-motion-r4-04`，删线后的收录版为 `outline-motion-r4-05`；空间数据仍为 `outline-street-r4-02`。

这份说明记录能重用的方法和约束，具体代码与文件校验值由场景目录、manifest 和验证记录承载。它适用于一个有真实位置依据、可连续走动的小街区近景，不把整张城区总览改成此种渲染。总览的手绘栅格规则继续由 [HANDPAINTED_MAP_ART](../HANDPAINTED_MAP_ART.md) 管理；位置、时间、session 和正式入口继续归 [ARCHITECTURE](../ARCHITECTURE.md) 的既有所有者。

## 先确定要保留什么

这块场景的辨识度来自街道朝向、两侧建筑的高度关系、建筑退界形成的开敞前场、大小不齐的底商和后方塔楼。绘制首先保留这些关系，才轮到人物、车、树和动态线。不能用统一窄人行道、整齐店面阵列、几层楼图标替代已经核对的关系。

输入分为三类，不能相互冒充：

| 输入 | 用途 | 约束 |
| --- | --- | --- |
| 带坐标的道路、建筑轮廓和来源记录 | 建立方向、位置、尺度与稳定 ID | 原轮廓留存；展示简化另存；高度单列证据 |
| 多点街景与卫星/俯视参考 | 核对地面退界、街侧、层数类别、遮挡与前后关系 | 保留拍摄日期及视向；现代图像不自动代表回忆年代 |
| 用户纠正与视觉选择 | 修正地点身份、取舍与表现方式 | 当前明确纠正优先；视觉认可不转化为历史认证 |

具体地理位置纠正直接更新选定场景数据；只有暴露了采集、配准、过滤或验证方法问题的修改，才提炼进流程。文档不复制个人原话或逐次位置修正日记。

## 按行走视线选择前后轮廓 — 2026-10-28

临街审查首先回答画面中的前后关系：低层门脸挡住了什么、后排楼从哪里露出、是否有重要空隙、退界和高度对比。门脸处于正确街段和路侧、大致范围与相邻体量相符即可；逐店米级位置、精确店宽和不可见的结构连接不是默认验收目标。已有用户指认和大体空间认可应作为后续底稿，只有影响辨识、前后关系或真实通行的矛盾才重新打开核验。

熟悉且接近行走视线的前排轮廓保持清楚。陌生或没有记忆意义的后排楼，只交代辨认前后层次所需的露出部分：上部可以省去轮廓、少画乃至不封闭，填色可回到安静的背景处理。不要在省略高度处新增一条横向屋顶线，将原高楼误画成矮楼；原占地、朝向、高度类别仍留在空间资料中。被选择为完整地标的高楼继续保留辨识所需的真实高度关系。

用户进一步指定约五六层作为普通街景体量的大致绘制范围：较矮的楼保留完整轮廓，更高的普通后排楼保留这一高度带，再向上开放或留白。下部填色和轮廓应足以让这五六层读得出来，不能过早淡去而只剩一两层门脸。层数和终止高度允许近似，不要求逐栋核准，更高部分也无需为了表现而查清总层数；源资料照常保留。选择完整呈现的辨识地标仍按前述规则处理。

先用实际步行相机的近处、斜向和稍远视图判断哪些部分能看见、是否值得画。近处视野未涵盖楼顶时，无需拉远或抬高日常相机来展示完整楼体。审查用远景仅用于比较层次，不能反过来要求补齐普通行走看不到、用户也不关心的上半部。此处的省略是有意的表现选择，与来源未知分开记录；不得将细节缺失全部展示为待核警告。

## 从证据到可行走场景

1. **划定最小范围与观察方向。** 写清路口、街侧、四至、关键建筑和真实 consumer 相机。先对齐哪个方向是北、哪侧在前，避免拿一个斜向全景画面直接搭左右对称的街谷。
2. **交叉检查多点位。** 用不同路段的可见面与俯视图核对前后层次、重要间隔和大致退界，按上述表现目标停止取证。全景拼接与广角会拉伸边缘，近大远小也会夸大楼高；不能直接拿画面宽高比作为米制尺寸。地图视口中心不是入口坐标，地图坐标系也不能直接当 WGS84 使用。
3. **冻结空间底稿。** 统一局部米制坐标、朝向和源 ID，保留源轮廓与简化展示轮廓。道路、导航和碰撞使用同一坐标框架。退界、独立底商、开敞前场与后排高楼分别可改；外观简化不能挪动地点或凭空开门。
4. **先看素模与路线。** 连续走到范围端点，转向看楼高、间距和遮挡。空间未对齐时不靠线条或配色修饰。只构造有意义的局部，不为一个入口补完整小区内部。
5. **建立轮廓语法。** 用下面的连接和遮挡规则画主线，再验证实际显示大小。人物、车辆、树分别遵守有限笔数；动态短线最后添加，不能补救建筑主轮廓本身不准。
6. **局部修改、固定视图复查。** 同位置、视向、缩放检查前后变化，同时转到正面、侧面、斜向与近裁剪处检查。只修改受影响的对象/画法，不重新生成所有已认可空间。
7. **按修订入库。** 选择唯一可启动版本，保留必要代码、数据、依赖许可、校验值、流程和简洁验证结果。试画、截图流水账、原始照片与私人素材继续留在库外。

Marble 2 重建可帮助检查空间，但生成结果本身不是地理或历史证据。本样本运行时使用实时几何和轮廓，没有依赖生成图片、街景纹理或远端模型。以后选择工具时以是否改善上述空间判断为准，不把模型名称当作交付要求。

## 轮廓要靠结构成立

主线保持平直、流畅、连续；次级线只在少量边角表示运动或声音。配色次于线条组织。不要用随机抖动、密集窗格、排线、噪声、重复描边或表面涂鸦制造所谓手绘感。

| 对象关系 | 绘制规则 | 检查重点 |
| --- | --- | --- |
| 门框—建筑 | 门的倒 U 形与楼底相接，删去开口对应底线 | 一个连续开口；避免闭合矩形压在楼底线上 |
| 窗框—建筑 | 窗框与边角、楼底及相邻窗之间留清楚间距 | 真实外法线与面方向一致；不因相机角度合成黑团 |
| 轮圈—车体 | 前方轮圈使后方车体线局部让开；挡风线留边距 | 侧向与斜向保持明确分工；端视过窄轮圈可省略 |
| 树—路沿、细物体之间 | 按前后深度，保留前景线、裁掉后方线的一小段 | 空隙随视角更新；不在灰色路面刷白色光晕 |
| 建筑大体量—其他物体 | 使用正常填充与深度遮挡 | 不把小物体的留缝规则扩大成整栋建筑的装饰白边 |
| 人物头—躯干 | 头、颈、躯干、四肢构成一条闭合周界 | 不是球形头顶在身体上；步态中不自交、不翻面 |

原型使用屏幕像素笔宽，避免近远变化时轮廓忽粗忽细。粗线跨越实体边界，可能被自己的填充切薄；当前代码采用与像素笔宽相关、受上限约束的微量深度偏移，仍保留前方物体的遮挡。不能用整体关闭 depth test 修复。

小物体遮挡用投影椭圆/线段遮罩裁切黑线片元，并跳过物体自己的笔画。遮罩只在正深度有效；跨过视点平面的椭圆必须跳过，避免异常投影误删半屏线条。线段深度用透视对应的倒数插值。近乎端视的轮圈用不同显隐阈值避免抖动。这些是当前 Three.js 实现策略；其他渲染器可以替换实现，但要保留同样的视觉结果。

## 动态是少量标点

建筑短线随行走触发，顺势弧与放射弧交替；同一时刻只强调一处建筑。停止后收完即停，单纯转相机不触发新的建筑提示。附近短线略长，稍远可见树木也可轮流获得提示。商店门窗偶尔给两根声音弧线，与汽车引擎提示共用名额，不能叠成新的密集层。声音线是表现符号，不是历史声源或音频记录。

**始终保持实黑与固定粗细，通过伸出、缩短、收起出现或消失，不使用淡出。** 树木微摆与人物腿部运动都应轻量；人物步态按实际移动距离驱动，停止回到站姿。菜单/隐藏页面暂停动态，减少动态偏好关闭环境短线和树摆动。

以下是本版调参起点，复用时需在新画面中重新验收，不能当作通用物理常数：

| 参数 | 当前值/预算 |
| --- | --- |
| 主线 / 细节线 / 地面线 | 3.5 / 2.9 / 2.2 CSS px |
| 小物体前景线外的留缝目标 | 约2.5 CSS px，受透视和抗锯齿影响 |
| 建筑短线 | 一组两根；近处长度倍率1.1—1.65；一轮5.8秒，伸出1.15秒、收起1.5秒 |
| 树木提示 | 一组两根；选择约58米内可见且投影足够大的树，约60米范围内绘制 |
| 声音提示 | 商店约18米内；一组两根，与汽车轮流；商店事件间隔约12.8秒 |
| 同时出现的环境短线 | 最多六根，属于上限而非必须填满的配额 |
| 车辆 / 树 / 建筑细节 | 每车最多四笔；树冠加树干两笔；每楼只选一个面，最多四个必要框 |

## 电线省略，路灯简化

用户明确选择不画电线：跨时期变化大，额外查证难以改善这段记忆表达，而且绘制与遮挡成本高。默认不研究、不生成、不保存电线布局，也不为了填空再加装饰线。路灯保留稀疏的简化轮廓，用于街道尺度感，不声称精确型号、位置和年代。

这项取舍可用于后续同类近景。只有某根电线/电杆本身承担明确记忆或事件意义、并被新的用户要求选中时，才作为单独局部对象重新处理；可见现代设施不自动成为历史场景的必画项。

## 验收、复用和正式接入

| 维度 | 必须取得的证据 | 不足时如何处理 |
| --- | --- | --- |
| 空间 | 多点位/俯视关系、源 ID、四至与高度类别；实际路径检查 | 标记未知/近似，不补造年代或精确路线 |
| 轮廓 | 正、侧、斜视与近裁剪下检查接缝、粗细、让线和填色 | 修复局部轮廓或遮罩，不移动真实建筑来迁就画面 |
| 动态 | 行走触发、停止收起、相机旋转、远树、店/车交替与数量上限 | 先减数量，保留主轮廓与注意力层级 |
| 可用性 | 独立启动、实际键盘/点击行走、转向、菜单与缩放 | 测试通过和实际浏览器通过分开记录 |
| 收录 | revision、文件哈希、依赖许可、文档链接、用户认可范围 | 未测项保持未测，不把旧版本证据标成当前通过 |

新场景优先重用连接规则、动画预算、验证方法与模块职责，替换地点数据和场景参数。`drawing.mjs` 负责展示，`ink-occlusion.mjs` 负责细物体让线，`motion.mjs` 负责动态短线，`avatar.mjs` 负责连续人物周界，`navigation.mjs` 负责局部行走；这些文件是本样本实现，不是另建一套项目所有权。

三里收录版现通过 `src/explorer/outline-stage.js` 接入原 overview→street 入口：位置/相机/路径归应用session，本地米制frame归spatial，工作合成层按time resolver的显式成员选择。渲染器按需加载；返回总览取消路径、停止RAF与输入，单个兼容stage最多保留60秒以便重入；过期、上下文不兼容或最终退出时才释放监听、观察器、导航与GPU资源。重新进入按入口上下文恢复，不能把缓存当作位置所有者。没有第二个场景localStorage位置所有者，也没有iframe或独立网页跳转。主总览继续使用手绘栅格与无人物规则。

扩区后的资源管理由 [RUNTIME](../RUNTIME.md#bounded-runtime-resources--dm-runtime-residency-20261027) 统一规定：先登记轻量空间范围和构建函数，再按完整相机视锥创建活动区块；离屏区块进入受数量、估算字节和时间限制的暖缓存，共用材质由场景统一释放。保留原380米远裁剪面及远处墨线，不按填色的雾距离删掉轮廓。这是绘制资源驻留优化，仍整包读取并校验场景JSON，没有加入网络按区块加载、自动LOD或全局路网层级。动态线与已认可的笔宽、遮挡和空间关系继续按原规则验收。

[三里近景](../../scenes/xinhua-sanli-outline/README.md)的 `sanli-outline-r5` 于2026-10-27获用户入库和集成认可，延续上面的主线语法。用户认可的Haring启发轮廓和UI配对仅用于这个近景及其导航；不自动改变整张总览或其他人物资产。

## 从路口扩展到街区

先保留原路口源对象，再按登记ID补齐当前选定区域。楼间主路、步道、绿地、广场、边界、门框与小物体分开建模；render与navigation消费同一份几何数据。栅栏缺口与门框共享端点，不能一份视觉开口配另一份碰撞缺口。绿地和明确非道路区域先从通行面扣除，入口通道另行保留。跨越障碍的连续线段也要验证，不能只检查路径节点。

路肩树与杂物筛选需检查对记忆地标的影响：自动净空过滤可能误删承担相对定位作用的对象。修订后同时检查树—路沿—容器的关系、楼体净距、近端通道与实际镜头。只有这些算法或验证教训进入流程；地点尺寸的来回微调仅留最终数据。

实景来源不可达时，按来源缺口处理。搜索索引或相册张数不等于看过照片，登录失败也不允许把相邻小区图片替代当前地点。公开源、已观察图像、用户选择、重建推断与未知继续分开。不要为填满地块补造未观察围墙、校门或年代。

## 导航UI与中文排字

场景主轮廓仍平直连续、表面安静；普通UI采用粗圆线、轻微不规则的封闭边框，少量放射短线和暖黄点色。菜单保留三条可识别横线；指南针箭头独立转动，不让整个轮廓持续摇摆；小地图保持北向固定，与真实位置同源。几何轮廓和导航数据不可为获得“扭”感而漂移。装饰SVG仅用于普通UI外框与指向符号，不代替总览建筑或植物美术。

中文使用本地[ZCOOL KuaiLe/站酷快乐体](https://github.com/google/fonts/tree/main/ofl/zcoolkuaile)原始字体，随包保留SIL OFL1.1许可。字形本身提供倾斜、圆钝和不齐节奏，不把每个字随机旋转。导航标题约18px，方向13—14px，微型地名和图例约10—11px；实际尺寸下检查拥挤和对比。菜单长文仍保留行距。Canvas文字必须在字体ready后重绘缓存层，否则DOM是新字体而地图仍是回退字体。中文cmap覆盖、网络字体成功、实际可读性是三个独立检查。

## 入库与主体接入流程

1. 先读任务相关的现行文档与已有任务包；从远端main准备干净分支，保留其他未提交美术工作。在开始构建前把范围留在repo，沙盒也一样：复用匹配任务包，至少有目的、精确基线、边界、验收、产物去向和状态。只选唯一认可修订的代码、场景数据、必要依赖和许可；试验快照、原始参考、登录过程、截图与一次性脚本不入库，不为每次试画另开审批。
2. 将源位置交给spatial frame，将位置/相机/路径接入session，将时间可见性交给已有resolver。工作合成层显式声明，不声称每个选择年代的完整旧貌。用相同稳定地点ID登记，哈希绑定data/art revision。改实现时同步受影响的文档owner。
3. 按需加载选定渲染器，隔离局部CSS，使用可取消输入监听与明确资源所有者。打开菜单暂停移动和环境动态；返回总览暂停兼容stage，有限保留后最终销毁。禁止保留沙盒自己的位置localStorage、无条件全局键盘监听或竞争的渲染循环。
4. 先检查完整diff和文档是否对齐：风格规则、interaction例外、session/登记接口、runtime与STATUS须描述真实行为；历史证据保留原修订，不把待验收实现写成已经通过。检查PR模板与范围后，再运行本次必要的测试、构建和可提前执行的CI。
