# 新华街：卫星参考 → SVG 构图 → 手绘候选

本批完成七里、五里西区、六里三个样组。使用内置 image_gen，完整提示词在 prompts.json。review.webp 上排为 SVG，下排为手绘和小尺寸预览。当前网站未接入这些候选。

## 为什么这样分

- 七里：资料称三栋塔楼和一栋电梯板楼；使用四个 OSM 建筑轮廓做组合候选，未逐栋对应楼号。西侧另有短楼，不因相邻就合入四栋清单。
- 五里西区：中介资料描述三栋 24 层塔楼、三栋六层板楼；与影像中的三种朝向低板和三个紧凑高楼体组合相符。五里东区不并入本样组。
- 六里：资料报七栋；本次人工勾出九个可见屋面段，**屋面段不等于楼栋**，折角与连接关系尚需匹配。不能以本稿声称九栋住宅。屋面描摹尚未纠正成地面轮廓。
- 官方四至说明四里在六里东侧、二里西侧。四里和六里可以同批制作，但保留独立边界和身份。

## 多层与批次

1. 全图层：将院子压成淡色轮廓和主要高低关系，建议最长边约 80–100px。本批 96px 只是缩小检查，不是已完成的专用远景画稿。
2. 小区层：本批主要用途，约 200–300px。保留长短、朝向、塔板组合，不依靠精细窗格识别。
3. 局部层：沿用同一构图数据，分出楼体、围栏、门口与独立店铺。未查证的店铺不画入。SVG 已分别分组；本批生成的整院 raster 尚不能任意拆出被遮住的立面，之后需按对象另生成。

路、文字、点击区域不进入本批图片。SVG 的 yard-wash、building-shells、frontage-reserved 分层；楼体有独立稳定的候选 ID。layout.json 保存原始像素形状和投影参数。修改某一块时先改底稿，再仅重出该院子/楼体，不能以生成像素反推真实坐标。当前 SVG 使用候选画面坐标，不已接入正式空间注册。

## 本轮检查与剩余问题

已检查 SVG 与生成稿的整体排列、三塔/低板的类型区别、无公共道路和文字、透明通道以及 200/96px 缩小效果。生成图重新安排了少量间距、窗层和绿化，不能宣称精确配准。手绘稿中的窗层不是实际层数，尤其不能拿画中的 8 条线替代资料中的 24 层。六里所有低楼被风格化压缩高度；屋面分段仍待合并确认。窗户、树木仍偏细，下一版可减笔触并压平院内细节。

生成图片是复合候选，不是三个正式可注册院子。未经逐栋地面锚点核对，不进入正式地图。没有浏览器验收、没有部署、没有历史真实性或用户画风批准。

## 文件

- qili.svg / wuli-west.svg / liuli.svg：可编辑中间稿。
- *-guide.png：实际传入 image_gen 的 SVG 渲染图。
- *-illustrated.webp：保留生成构图的透明候选。
- *-cutout.webp：按 alpha 外接框裁剪，保留透明，不重新绘画。
- catalog.json：尺寸、裁框与 SHA256；prompts.json：生成提示词。
- scripts/prepare-compound-study.py：从保留影像元数据、OSM 提取稿重建 SVG；需 Pillow、Node sharp。参考文件须另备，不随公开 repo 分发。
